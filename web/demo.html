How it works

  1. Write rulesDescribe each endpoint: fields, types, limits, patterns and cross-field conditions.
  2. Check themThe compiler catches contradictions and impossible rules before anything is deployed.
  3. Repair risky patternsRegexes that could freeze a server are flagged, proven with an attack string and safely rewritten.
  4. Generate validatorsOptimised Python and JavaScript code that checks every request in linear time.

What the results mean

Matching without backtracking

Generated pattern checks use DFA transitions, so matching is linear in the input. This does not bound compilation cost or make every surrounding request operation safe.

Field equivalence, with coverage

The checker covers scalar string fields: presence, length, enums and DFA checks. Conditions, scans, error behaviour, numbers, lists and generated code are outside it.

A witness proves a difference

Each shown request is replayed against both policy versions. No witness does not prove the versions are equivalent; unsupported results stay visible.
