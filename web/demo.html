RegexShield began with a question: could a regular expression cause expensive backtracking?

ShieldLang extends that work into a language for complete API validation policies. Its compiler checks declarations, builds intermediate code, applies optimizations, and emits Python and JavaScript validators.

The next questions are just as important: did the transformation preserve the field’s language? What request behaves differently after a policy edit?

Inspect the full evidence in Studio ↗
01

Matching without backtracking.

Generated regex checks use DFA transitions. This does not establish bounded compilation cost or make every surrounding request operation safe.

02

Field equivalence, with coverage.

The checker supports scalar string fields, presence, length, enums, and DFA checks. Conditions, scans, error behavior, numbers, lists, and generated code are outside that check.

03

A witness proves a difference.

A displayed request is replayed against both policy VMs. No witness does not prove that the policies are equivalent. Unsupported and incomplete results remain visible.
