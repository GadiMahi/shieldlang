Bypass Lab

A filter and the application behind it are two programs, and they don't always read the same bytes the same way. If the filter checks one interpretation (say, the raw text) and the application acts on another (say, after decoding percent-escapes), an input can look harmless to the filter and harmful to the application. Search a declared local experiment, inspect both readings, and reduce a replay-confirmed finding to its essential input.

  1. Pick a fixture
  2. Pick or type a candidate
  3. See both interpretations
  4. Read the verdict and local replay

What is searched: only the selected fixture's declared transformations and local application. Seeds come from its oracle, not the preset bypass examples. A finding requires policy acceptance, an oracle violation, and local replay. No finding within a budget is not proof of safety. Reduction preserves replay; it does not promise the shortest possible input. The fixture policy applies the oracle predicate to its own interpretation; it is not a compiled .shl policy. These experiments do not scan external websites or arbitrary ShieldLang policies.

Plain-English glossary (click to open)
Fixture
One named scenario: where the input goes (a body field, a path parameter), how the policy reads it, how the application reads it, and what counts as a violation.
Pipeline / stage
The ordered steps a side applies to the raw text before using it — e.g. percent_decode, nfkc, strip_nul. Different pipelines are what create the mismatch.
Policy-side view
What the filter ends up checking after its pipeline.
App-side view
What the application ends up using after its pipeline.
Oracle
An independent definition of “this is a violation” (for example “contains <script” or “escapes the allowed folder”). It is evaluated on the app's view and shares no code with the policy.
Local replay
The candidate is actually sent (loopback only) to a tiny local fixture application, to confirm the app really behaves the way the model says.
Confirmed
All three at once: the policy would accept it, the oracle says the app's view is a violation, and the replay confirms it. Anything less is “not confirmed”.
Negative control
A fixture where both sides read input identically. It exists to show the lab doesn't cry wolf.

Set up

1 Pick a fixture

What you're choosing: a pair of readings (policy vs application) and a definition of “violation”. The diagram below shows both pipelines.

2 Pick or type a candidate

Candidate = the raw text that will be run through both pipelines. The buttons load the fixture's own examples; you can edit them or type anything. Use manual evaluation below, or let the bounded search generate variations from the fixture oracle.

Search and reduce

Generate candidates using the declared transformations. The numeric seed makes mutation order reproducible; time limits can still truncate a run.

Up to 3 findings, 80 reduction checks per finding and a shared 5-second evaluation budget. Local replay is required for confirmed findings.
